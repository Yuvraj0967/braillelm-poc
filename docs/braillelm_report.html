Abstract

A braille→print proof of concept was trained twice on the same 480 sentences. The baseline read raw Unicode braille through the stock byte-level tokenizer. The native model added 177 braille-cell tokens, initialised their embeddings from the print strings they represent, and fine-tuned LoRA adapters. On the 120 held-out sentences, native translated every sentence exactly. Baseline translated none: it emitted nine distinct sentences, used 22 of the 138 corpus words, and matched the actor noun in 2.7% of cases. The comparison isolates tokenisation as the decisive variable at this scale; the corpus design limits what can be claimed beyond it. Sections 12–21 add the model and data cards, every test item, the comparison kit, and Appendix C.

Executive summary

What was tested · what holds

The project asked a narrow question: at fixed model size and data, does a braille-native tokenizer make braille→print translation work where the stock tokenizer does not? The answer on this corpus is unambiguous: yes, and the gap is qualitative, not incremental.

Two arms were trained from HuggingFaceTB/SmolLM2-135M on the same 480 UEB Grade 1 sentences: identical seed, one epoch, AdamW at 1e-3, batch 4, fp32 on CPU. The baseline fed raw Unicode braille to the stock tokenizer. The native arm added 177 tokens (27 corpus cells + 150 BPE merges), set each new embedding to the mean of the print-string embeddings it expands to, and trained LoRA adapters plus the resized embedding matrix and LM head. Evaluation used 120 held-out sentences, greedy decoding, and exact match as the primary metric.

Native produced 120 distinct, exact sentences (CER 0.0, BLEU 100.0). Baseline produced nine distinct sentences for 120 inputs (CER 63.8%, BLEU 4.0). The baseline did not fail by producing noisy translations; it failed by not conditioning on the input at all. All 120 outputs begin with “The” although 30 references begin with “A” and 3 with “My”. Its output vocabulary is 22 words, and 116 of the 138 reference words are never emitted. On the nine-word template it matches the final article 100% of the time and the actor noun 2.7% of the time. That is template completion, not decoding.

The mechanism is plausible and consistent with the measurements. Raw braille costs 3.00 tokens per cell (165 tokens per sentence), so the model must learn a mapping through a fragmented byte-level representation. Native costs 0.535 tokens per cell (29 tokens per sentence), with embeddings that already point at the right print fragments. Training loss separates the arms early: native falls below 0.3 by step 30 and reaches 0.002; baseline is still at 1.32 at step 120 and never converges.

Key findings

  1. Representation was the bottleneck. Same weights, data, optimizer, and seed. The only intended change was tokenizer plus embedding initialisation, and exact match moved from 0% to 100%.
  2. The baseline’s failure is structural. Nine outputs, 2.62 bits of output entropy (maximum 6.91), 22-word vocabulary, and near-zero accuracy on every content slot. It learned the corpus prior, not the dots.
  3. Efficiency is a second, independent gain. 5.6× fewer input tokens, 2.2× faster batched inference, and a prompt that fits the 128-token training budget that the baseline overruns on every sentence.
  4. The corpus is the ceiling on the claim. 138 words, three sentence patterns, and every test word seen in training. Native’s 120/120 demonstrates learnability on this distribution; it does not demonstrate generalisation.
  5. The truncation confound was tested and dismissed. The baseline lost an average of 8.5 tokens from 61% of its training prompts at 192 tokens. A control at 256 tokens — where no row is truncated — still scores 0 / 120 exact, CER 60.2%, BLEU 4.2, with 15 distinct outputs. More context slightly diversified the prior; it did not create input dependence.
What would overturn the verdict A word- or template-disjoint test set on which native drops sharply; or a probe showing that native copies template endings rather than reading cells. Neither has been run. Both are P0 in §10. The 256-token control has now run and did not overturn the result. Until the two remaining tests pass, the defensible claim is: the representation works on this corpus.

Question and design

A matched two-arm comparison

Hypothesis: at fixed model capacity and training data, braille→print quality is limited primarily by how braille is represented to the model, not by the model’s size.

If true, a small base model should learn the mapping when each braille cell costs about one token and its embedding starts near the print fragment it encodes; the same model should fail when the same dots are spread across three byte-level tokens with no print-aligned initialisation. The experiment changes only that representation.

The intended variables are the tokenizer, the embedding initialisation, and the parameters that consequently become trainable. The max_len difference is a consequence of the representation, not a tuning choice: native fits comfortably in 128 tokens, while baseline needs 165 tokens for braille alone. At 192, every answer survived intact, but 61% of training rows still lost prompt tokens from the left (§9).

Evaluation protocol

  • Exact match (primary). The whole output must equal the reference after whitespace trimming. It is insensitive to BLEU’s behaviour on short sentences and is the metric a user experiences.
  • Character error rate. Mean Levenshtein distance divided by reference length, per sentence. It measures severity when outputs are wrong.
  • sacreBLEU. Corpus score with the default tokenizer. Reported alongside its four n-gram precisions and brevity penalty so that template matching is visible.
  • Tokens per cell. Braille-side token count under each model’s own tokenizer, divided by the number of Unicode braille cells. This is the efficiency claim.
  • Output diversity. Distinct outputs, Shannon entropy, largest cluster, and output-vocabulary coverage. These expose input bypass, which CER and BLEU alone can hide.
  • Position accuracy. Per-word-slot match on the 112 nine-word test sentences. It localises where a model succeeds and fails inside the template.
  • Latency. Greedy decoding on eight test sentences after one warm-up, measured at batch 1 and batch 8 on the same machine.
Out of scope Grade 2 contractions; digits and punctuation beyond the period; line breaks and multi-sentence documents; novel vocabulary; other model sizes; GPU or bfloat16; sampling; human evaluation; production throughput. Any of these could change the measured gap.

The round-trip filter guarantees clean labels: every kept pair is one the engine can invert, so accuracy differences cannot come from annotation noise. The price is selection bias toward strings the engine handles perfectly — which, for this corpus, is all of them. The shortcut is elsewhere: a random split shares words and sentence patterns between train and test. A model can score well by learning which word belongs in each slot and copying the rest.

That is not a hypothetical. It is precisely the baseline’s behaviour (§8): it fills the template with high-frequency fragments and ignores the input. Native’s 120/120 therefore establishes that the representation is sufficient to learn this distribution. It does not establish that the system reads arbitrary braille, and it cannot, because the test set contains no arbitrary braille.

Why “bigger” is not the next step Expanding the same generator to 1,500–2,000 sentences would add more combinations of the same 138 words and three patterns. It would lower training loss and raise confidence on this distribution, but it would not test generalisation. The next corpus needs new words, new syntax, and a split that holds out words or patterns — otherwise more data measures memorisation more precisely.

Method

Tokenisation · BKFT · LoRA

4.1 Two tokenisations of the same dots

The baseline sends the braille string as Unicode text. SmolLM2’s byte-level BPE has no braille-aware units, so a cell shatters into roughly three tokens: 3.00 tokens per cell, 165.3 tokens per sentence. The native arm starts from the 27 distinct cells the corpus uses (letters, space, capital sign, period) and learns 150 BPE merges over training braille, never merging across spaces. The result is 177 added tokens, a vocabulary of 49,329, and 0.535 tokens per cell — 1.87 cells per token, 29.4 tokens per sentence.

4.2 BKFT initialisation

Each added token starts at the mean of the base model’s embeddings for the print text it expands to. Capital, number, and space indicators expand to nothing, so they do not pollute the average; when the LM head is untied, the same rows are mirrored there. For a token mapping to the, the new row is exactly the centroid of the embeddings of the pieces that spell it. The check in the project’s wiring test confirms this is numerically exact.

Why it matters: a random new row must be moved into place by gradient descent from 480 examples. A print-aligned row already sits in the region the model uses to represent that text. The experiment does not separate the contribution of the extra tokens from that of the initialisation — they are delivered as one design — but it does show the combined design is sufficient.

Small models tie input and output embeddings. Resizing the vocabulary therefore resizes both, but LoRA alone would leave the new rows frozen; modules_to_save makes them trainable. This is why PEFT reports 57.3M trainable parameters (29.85%) for native — most of that is saved embedding copies, not adapter weights. The baseline has 460,800 trainable parameters (0.34%). Examples longer than max_len are left-trimmed so the answer is never cut; the consequence for the baseline is quantified in §9.1.

8.1 Three mechanisms

Input bypass. The baseline emits one of nine sentences regardless of the dots. All 120 outputs start with “The”, although the references contain 87 “The”, 30 “A”, and 3 “My”. Its output vocabulary is 22 words; 116 of the 138 reference words never appear. The model has learned the corpus prior and stopped there.

Template completion. Position accuracy (Fig. 2) shows what it did learn: the final article 100%, the first article 70.5%, the second article 39.3%. These are the most predictable slots in a templated corpus. Content slots sit at 0.9–6.2%. It is completing a frame with frequent fragments, not decoding cells.

Vocabulary starvation. The nine prototypes are not verbatim training sentences — none of the nine appears in the training file. They are novel recombinations of high-frequency fragments: “fisherman”, “captain”, “stone bridge”, “silver coin”, “the storm”, “the morning”. That rules out simple memorisation of a single row while confirming that the learned object is a distribution over phrases, not a mapping from input.

8.2 It is not a near miss

The best baseline row matches 66.7% of its reference words and still has 30.8% character error; the median row is 64.0% CER. Bigram precision is 3.15%, so almost no two-word sequence survives. A model that was “nearly there” would show high unigram and moderate bigram overlap with input-sensitive variation. This model shows neither.

8.3 What native’s zero error does and does not show

Native is exact on all 120 rows, with 120 distinct outputs. That is strong evidence that the representation carries enough information to learn the mapping and that the model uses it: output diversity rules out a decoded prior. It is not evidence of open-domain translation. The test words are all in training, the patterns are the training patterns, and training loss of 0.002 is consistent with a near-deterministic transliteration of a closed distribution. The next test must introduce words and structures the model has not seen.

The defensible claim On a closed, templated corpus, a 135M model with braille-native tokens and print-aligned embeddings learns braille→print exactly, while the same model with a stock tokenizer does not learn to condition on the input at all.

9.1 The truncation confound, precisely

At max_len = 192, 61% of baseline training rows exceeded the window and lost prompt tokens from the left: 2,485 tokens in total, 8.5 per affected row — about 2.8 braille cells out of 55, usually from the beginning. That is a real handicap, so the control was run rather than argued: the same recipe at max_len = 256, where no training row is truncated (mean loss 2.317, versus 2.421). It scores 0 / 120 exact, CER 60.2%, BLEU 4.17, with 15 distinct outputs from a 29-word vocabulary. Extra context made the prior slightly richer and the sentences slightly closer; it did not create input dependence. The confound is eliminated, and the conclusion survives it.

9.2 What the confidence intervals say

With 120 items, 120/120 has a 95% Wilson interval of 96.9–100%; 0/120 has 0–3.1%. The test set is large enough to establish that the arms are not close. It is not large enough to estimate a 1% error rate, which matters for a production claim. Nothing here supports a per-character reliability claim beyond “no errors in 120 sentences”.

Bottom line on validity The comparison is internally valid: same model, data, optimizer, and seed, with one intended variable. Its external validity is low by construction. The report should be read as a controlled demonstration that the representation works — not as a benchmark of braille translation.

Decision and next steps

Proceed · gate 1 open

Decision: proceed to a scoped next phase. The representation result is strong and the engineering path is clear. The baseline’s failure has now survived a fair context budget; the remaining gate is lexical independence. The next phase should test that before scaling the recipe.

10.1 On expanding the corpus

Do not expand the current generator to 1,500–2,000 sentences as the next experiment. More combinations of the same 138 words would reduce training loss and make the model more confident on a distribution it already solves, while adding no evidence about reading. If the goal is a larger corpus, change its composition first: new lexical domains, varied syntax, verb tense and agreement, names, numbers, punctuation, and multi-line layout. Hold out words and patterns, not random rows. A 600-sentence diverse set is worth more than a 2,000-sentence templated one.

10.2 Deployment notes

The native model ships as a merged fp32 checkpoint: 163.0M parameters, 652 MB, with an untied LM head created by the merge. That is larger than the 135M base (538 MB) because the head is duplicated. The adapter alternative is 1.86 MB on top of the base, but the native adapter also saves the resized embedding and head, so the merged artifact is the simpler delivery. For production, quantisation is the first lever; the 5.6× token reduction is the second, and it applies to every input regardless of model size.

Gate status, in one sentence Gate 2 is met: the 256-token baseline still scores 0 / 120. Gate 1 remains open: native must hold up on a word- or pattern-disjoint set. Until it does, present the result as a proof of representation, not as a translation benchmark.

12.1 Intended use, stated narrowly

Intended. Short, uncontracted UEB Grade 1 sentences drawn from the 138-word templated family used in training; CPU inference at batch 1–8; comparing tokenisation and embedding strategies at small model scale.

Not intended. Grade 2 contractions, digits, punctuation beyond the period, line breaks, multi-sentence documents, literary or technical braille, or production accessibility use. Unseen words and syntax are untested (§9, §10).

20.2 Noise and comparison

At n = 120, a score near 100% has a 95% Wilson interval of about ±3 points; near 50%, about ±9 points. Two models run on the same 120 items should be compared per row (paired), not by subtracting headline percentages. A gap of 2–3 rows is not a ranking.

Appendix B — Terms

  • BKFT — braille-knowledge fine-tuning: initialise each added token from the mean of the base embeddings of its print expansion.
  • UEB — Unified English Braille. Grade 1 is uncontracted, one cell per letter; Grade 2 uses contractions.
  • CER — character error rate: Levenshtein distance divided by reference length. 0 means identical strings.
  • PEFT / LoRA — parameter-efficient fine-tuning with low-rank adapters attached to attention projections.
  • Tokens per cell — braille tokens consumed divided by Unicode braille cells in the input; lower is more efficient.
  • Prototype — a complete output sentence that the baseline emits for many different inputs.
